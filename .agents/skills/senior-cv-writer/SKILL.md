# Writing an Evidence-Led Senior CV

Senior tone comes from clear system responsibility, not adjectives or speculative impact. State what the candidate owned or built, keep the scope concrete, and stop when the evidence stops.

## Drafting method

1. **Separate facts from interpretation.** Use supplied work history, verified evidence, and confirmed outcomes. Treat task titles and PR counts as leads, not proof of impact.
2. **Write `responsibility + system/workflow + concrete scope`.** Prefer `Owned the transition to organization-scoped tenancy across entity keys and API boundaries` over a list of tickets.
3. **Add an outcome only when it is known.** Otherwise end the sentence. Never infer security, performance, reliability, adoption, revenue, or compliance impact from the technology alone.
4. **Group related work.** One payment-systems bullet is stronger than separate bullets for 3D Secure, a webhook fix, and a Stripe bug. Use a scope summary only for a new category.
5. **Preserve the target role.** For senior backend roles, lead with systems, data, infrastructure, and production responsibility. Keep frontend, desktop, ML, and OSS work when relevant.

## Wording rules

| Prefer | Avoid |
|---|---|
| `Owned`, `Built`, `Configured`, `Migrated`, `Contributed to` | `Solely`, `world-class`, `significantly improved`, `robust`, `cutting-edge` |
| `Built payment and subscription workflows across backend and UI` | `Delivered Stripe 3D Secure and strengthened reliability` |
| `Owned storefront and campaign delivery across product discovery, merchandising, SEO, and landing pages` | A feature inventory such as `wishlist, sliders, infinite scroll, and more` |
| Generic system labels when names are sensitive | Internal project names or customer names without approval |

- Do not use literal `And more...`; if broader scope is important, name the categories precisely.
- Do not write `solely` unless being the sole contributor is material and the candidate explicitly wants to foreground it.
- Use `AWS` in skills when the candidate used many services. Name a specific AWS service only when it is central to a verified experience bullet.
- Use regular hyphens with spaces for punctuation (`scope - detail`) and retain closed hyphens inside compound terms (`multi-tenant`, `end-to-end`). Write `3D`, not `3-D`.

## Pressure-test failures to prevent

Baseline errors turned KMS isolation into “strengthening cryptographic key handling,” a tenant migration into “establishing clearer ownership,” and 3D Secure into “enabling strong customer authentication.” Those outcomes were not provided. Remove them or ask for evidence.

## Final check

- Can the candidate explain and defend every verb, scope, and outcome?
- Does each bullet describe a system responsibility rather than a ticket list?
- Are unsupported benefits, metrics, and seniority claims absent?
- Is the ATS master the factual source of truth, with HTML/print variants and parent CV notes synchronized?
- After changing an HTML CV, has desktop, mobile, and print layout been rechecked before export?
